# Constraint 0070

## Title
Agent operational standards and submission protocols

## Description
- [CS-0070.1] **Mandatory Clearance**: The agent is STRICTLY FORBIDDEN from performing `git commit` or `git push` operations without explicit, unambiguous clearance from the user in the current session.
- [CS-0070.2] **No Assumed Approval**: Even in autonomous modes, clearance for version control mutations MUST be requested and granted for every distinct task.
- [CS-0070.3] **Local Build**: The agent MUST perform a successful local build (`mvn clean test`) of all affected components.
- [CS-0070.4] **Full Test Pass**: The agent MUST execute and verify that ALL relevant unit and integration tests pass successfully.
- [CS-0070.5] **Deletion Analysis**: The agent MUST perform a deletion analysis to confirm that no unintended feature or interface loss has occurred. Any deletion must be justified.
- [CS-0070.6] **Impact Summary**: The agent MUST provide a concise summary of changes explaining the "Why" and "How", along with an impact analysis on dependent modules.
- [CS-0070.7] **Review Recommendation**: The agent MUST recommend a manual review of code changes, highlighting any areas of complexity.

### 4. Deletion Protection and Modification Safeguards
- [CS-0070.8] **Caller/Callee Impact Analysis**: Any modification or removal of an existing method signature must be preceded by a documented caller/callee tree analysis ensuring downstream components are unaffected.
- [CS-0070.9] **Test Modification Justification**: Modification of existing tests is strictly forbidden without written justification explaining why the assertions, parameters, or test contract had to change. Deleting an existing test without human authorization is prohibited.
- [CS-0070.10] **Two-Phase Human Review Protocol**:
  - **Phase 1 (Architecture & Safety)**: User/reviewer evaluates Target Feature IDs, Caller/Callee impact summary, Deletion justification, and Coverage Delta.
  - **Phase 2 (Syntax & Verification)**: Reviewer evaluates code quality, null-safety preconditions, static analysis reports (Checkstyle/PMD: 0 violations), and test results.
- [CS-0070.11] **Standardized Submission Template**: All modification summaries submitted to the user prior to commit clearance must include:
  1. *Features Addressed* (`[REQ-*]`, `[FR-*]`, `[TSK-*]`).
  2. *Impact Analysis Summary* (Affected modules and caller trees).
  3. *Deletions Justification* (Explicit reasons for any removed methods, fields, or tests).
  4. *Verification Performed* (Functional, Worst-Case, Stress test outputs, Checkstyle/PMD status).

## Rationale
Autonomous agents can rapidly propagate unintended regressions if changes are not strictly bounded. CS-0070 establishes strict submission guardrails, ensuring that all code modifications, deletions, and source control operations remain transparent, safe, and explicitly approved by the human engineer.

## Verification
- **Session History Auditing**: Explicit user approval instructions must be present in conversation transcripts before any `git commit` or `git push` is invoked.
- **Pre-Submission Output Logs**: Local `mvn clean test` logs showing 100% test pass rate and 0 Checkstyle/PMD violations.
- **Deletion Verification**: Git diff inspection confirming that any removed methods, fields, or tests are accompanied by explicit justifications.
