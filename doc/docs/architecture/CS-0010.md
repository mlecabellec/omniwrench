# Constraint 0010

## Title
Project's quality standards

## Description
This set of constraints defines the general quality standards for the Omniwrench project.

- [CS-0010.1] All code shall be associated to a requirement, a feature request, a task or a bug fix.
  - [CS-0010.1.1] Each class, methods, field, control structure, consistent block of statements shall be associated to a requirement, a feature request, a task or a bug fix.
  - [CS-0010.1.2] Association of code to a requirement, a feature request, a task or a bug fix shall be done using a comment block with the reference of associated requirement, feature request, task or bug fix.
- [CS-0010.2] Every requirement, feature request, task or bug shall have a unique structured reference usable in any code or documentation file.
  - [CS-0010.2.1] Requirements reference format shall be structured as follow (regex): `REQ-[0-9\.]{5}`
  - [CS-0010.2.2] Feature request reference format shall be structured as follow (regex): `FR-[0-9\.]{5}`
  - [CS-0010.2.3] Task reference format shall be structured as follow (regex): `TSK-[0-9\.]{5}` or `TSK-[0-9]{8}-[0-9]{3}`
  - [CS-0010.2.4] Bug reference format shall be structured as follow (regex): `BUG-[0-9\.]{5}`
  - [CS-0010.2.5] Bugfix reference format shall be structured as follow (regex): `FIX-[0-9\.]{5}`
- [CS-0010.3] **Structural Size Boundaries**:
  - [CS-0010.3.1] No method body shall be longer than 200 lines. A limited number of waivers are authorized if the method length is justified by an inline comment block explaining why further decomposition would be detrimental to performance, clarity, or logical atomicity. Waivers must be reviewed and approved by a senior architect.
  - [CS-0010.3.2] No class body shall be longer than 1,600 lines. Classes exceeding this limit must be refactored into cohesive modular sub-components or delegated strategies.
  - [CS-0010.3.3] A comment shall be inserted in each code block to explain its purpose. No executable code block without comments shall be longer than 5 lines.

## Rationale
To ensure end-to-end traceability between architectural specifications, user requirements, AI agent operations, and physical source lines, while enforcing strict readability, maintainability, and structural sizing limits across the codebase.

## Verification
- Checkstyle and PMD static analysis rules scanning for traceability tags and line length limits.
- Automated CI scripts asserting that every public class and method declares its traceability comment.
- AST / Checkstyle method and file length checks verifying [CS-0010.3.1] (<= 200 lines) and [CS-0010.3.2] (<= 1600 lines).
