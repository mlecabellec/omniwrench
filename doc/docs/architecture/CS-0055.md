# CS-0055: Zero-Mock Production Mandate & Verifiable Runtime Realism

## 1. Scope & Intent
This coding standard enforces that all business logic, tools, adapters, background jobs, and plugins in Omniwrench must execute **genuine, verifiable implementations**. The presence of simulated mocks, fake hardcoded return values, or stubbed placeholders in `src/main` is strictly prohibited.

---

## 2. Core Directives

### 2.1 Complete Implementation Obligation
Every requested feature, method, and API endpoint must be completely implemented with real I/O, actual subprocess invocations, true network communication, and real disk manipulation.
- **Prohibited**: Returning canned static strings or mock payloads where real tool execution was requested.
- **Prohibited**: Mocking internal engine components within production code paths.

### 2.2 Test Verification Realism
- Test cases verifying local LLM inference, model downloads, and file manipulation must execute real operations against actual files, real models (e.g. Gemma E2B), and real filesystem structures.
- Tests that download ephemeral test models must verify real token completions and automatically clean up downloaded assets upon completion.

### 2.3 Automated Static Analysis Enforcement
- Static analysis checks (ArchUnit and PMD rules) will scan `src/main` to detect any unauthorized mock frameworks (e.g., Mockito in main sources) or dummy placeholder returns.

---

## 3. Compliance Checklist
- [ ] No `Mock*` classes or mock dependencies in production modules (`src/main`).
- [ ] All tool operations interact with real OS filesystems, processes, and network sockets.
- [ ] Model downloads verify actual cryptographic SHA-256 hashes against downloaded bytes.
- [ ] Clean teardown hooks ensure test assets are deleted after test execution.
